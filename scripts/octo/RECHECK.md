# Речек

В новом чате можно написать «Речек: Первый MCC, Второй MCC». На ноутбуке должны быть открыты SproutG 2.4.0 или новее и RDM с подключённой общей папкой. В профиле Octo должен быть выполнен вход в нужный управляющий аккаунт. Обработчик находит страницу Performance или открывает её при запуске профиля и сверяет имя MCC. Дочерние страницы он открывает по ссылкам из таблицы.

```powershell
node scripts/octo/recheck.js run "Первый MCC" "Второй MCC"
node scripts/octo/recheck.js review "Первый MCC"
node scripts/octo/recheck.js status ID
node scripts/octo/recheck.js resume ID
```

`run` сохраняет результат в SproutG через его штатную очередь записи и перечитывает строку из рабочей таблицы. `review` показывает расходы, требования и предложенные изменения дат. Номер аккаунта, включая ведущие нули, должен совпадать в Performance и SproutG. Для каждого MCC сравниваются полный список строк SproutG и список Performance. При расхождении проверь фильтры в Performance. Собранные данные и причина остановки остаются в `%LOCALAPPDATA%\SproutG-Octo\rechecks\ID.json`.

Расход берётся из колонки Cost после подтверждения периода All time. Если таблица показывает число без знака валюты, используется указанная для этих профилей валюта USD. Пустая дата речека получает сегодняшнюю дату по Минску, пустой статус получает плюс. Существующий комментарий при отказе дополняется строкой «Замена видео».

У активного аккаунта проверяются открытые задачи Advertiser Verification. Два варианта требований к документам записываются в статус верификации U. Если уведомлений несколько, обработчик просматривает их по очереди. Сумма берётся из красного предупреждения об оплате и должна быть доступна в списке PrePay. Если предупреждение требует оплаты и не содержит суммы, применяется 20$. У аккаунта с нулевым расходом без этих требований проверяются видеообъявления и даты видеокампаний. Новая дата окончания — через семь календарных дней после речека.

Если обработчик встретил другой вариант страницы, посмотри профиль, аккаунт и этап в отчёте. Для чтения структуры экрана используй `node scripts/octo/recheck.js inspect "Имя MCC" policy 01`. Доступные экраны — `inventory`, `policy`, `campaigns`, `ads`. После исправления продолжи по ID. Если результат сохранения даты неизвестен, при возобновлении сверяется дата в Google Ads.

Запись идёт последовательно. Если Apps Script принял изменения, а в таблице ещё старые значения, обработчик объединяет до трёх таких строк для сверки. Интервалы между чтениями увеличиваются до пяти минут. Обработчик ждёт около часа и продолжает очередь, как только значения появляются в таблице. Если задержка дольше, ожидаемые значения остаются в журнале. После восстановления связи `resume ID` продолжает ту же проверку, в том числе на следующий день. Повторный запуск с тем же списком MCC подхватывает журнал с ожидающими записями. В конце каждого MCC все расходы и отметки сверяются одним чтением профиля.

## Windows Server

На ноутбуке команда `node scripts/octo/recheck.js stage` копирует пакет из проекта в общую папку RDM.

Пакет обработчика расположен в общей папке `\\tsclient\Q\recheck-tools`. Для первого подключения или переустановки выполни в серверном сеансе PowerShell одну команду.

```powershell
& '\\tsclient\Q\recheck-tools\setup.cmd'
```

После входа в Windows обработчик запускается ярлыком «SproutG Recheck» и ждёт общую папку. Подключение к Octo использует локальный порт 58000. Обновлённые файлы пакета обрабатываются между заданиями.

Для переключения закрытых профилей используется установленный в серверном сеансе обработчик `profile-control.ps1`. Если Octo показывает кнопку запуска только значком, чат может открыть нужную строку по свежему снимку списка профилей. При самостоятельном запуске можно открыть профиль в Octo и продолжить командой `resume ID`.
